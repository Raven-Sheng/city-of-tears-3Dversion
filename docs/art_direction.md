## 2. 参考相机与空间读法

主参考是带视差的二维分层画面，不是单一视点的透视图。样板用下面这台相机把它读成三维：

| 参数 | 取值 |
| --- | --- |
| 相机 | `CAM_REF_Statue`，透视，水平视线（不俯仰） |
| 位置 | X 8.5、Y −36、Z 2.2 |
| 焦距／画幅 | 28.6 mm／36 mm，纵向镜头位移 0.1874 |

- X 8.5 是参考图画面中心相对雕像轴线的偏移。
- 距离 36 来自参考图内部的视差：基座正面铭牌比主像中线偏左约 0.8 单位，与「基座正面比主像近约 3.4 单位、相机在右侧 8.5 单位」相符。
- 视线高度取 2.2 并用镜头位移把画面上移，使竖线保持竖直、地面只露出窄窄一条，接近横版画面的读法。
- 不在游玩平面上的物体沿这台相机的视线摆放：先在参考图上量出表观位置，再按所选进深换算世界坐标。这样对照视角保持参考构图，同时每个物体都有真实进深。换算函数是 `scripts/build_plaza.py` 里的 `W()`。

由此带来的判断（证据等级见资产表）：

- 雕像轴线在游玩平面上，路灯在轴线两侧对称。
- 喷泉后面带尖饰的冠形铁艺屏和叶片玻璃是**独立于雕像的物体**：`Lower_City_statue.jpg`、`Lower_City_statue_upper_right.jpg`、`Materials_02.jpg` 和雨景视频里它相对雕像的位置都不同（B 级）。它的实际进深无法确定，样板放在雕像后方 9.2 单位（C 级）。
- 三尊披覆像：左侧一尊与主像大致平齐，右侧一尊靠前，带圆形面具的一尊在主像左后方。这是比较主参考和用户近景图得出的——两张图相机偏移不同，右像在两图中相对主像的位置差了约 0.3，说明它比主像靠前；面具像差了约 0.3，方向相反，说明它在后面（B 级）。
- 广场后方的带栏杆圆拱墙按高架廊处理，桥面与高台同高（B 级）。雨景视频中拱洞透出亮光，说明拱是通透的。

**这种读法的限度。**游戏里各视差层随镜头位置和缩放各自移动，不服从同一台透视相机。`Materials_02.jpg` 是同一座喷泉在另一个缩放下的截图，图中路灯相对雕像的位置与主参考不一致，就是这个原因。所以近景对照相机 `CAM_REF_Materials02` 只用来比构件造型，不比各层之间的相对位置。

所有石、壳、铁材质共用四条规则，用来接近参考那种手绘的明暗组织：

1. 低频噪声在暗、亮两个基色之间变化。
2. **朝上的面更亮（混入 2.4 倍基色，权重 0.7）且粗糙度降低约六成**，雨中顶面有湿亮感，立面更哑。
3. **轮廓处压暗**（视线与表面夹角大于约 50° 时逐渐混入 0.1 倍基色），给形体一道深色勾边。
4. 花瓣沿中线有一道暗色叶脉，边缘有一圈浅色；高架廊、东侧楼和远处灰模墙面有程序石缝（砖宽 1.25、层高 0.56）。

试过第五条规则「凹缝压暗」（用环境光遮蔽节点把接缝和褶皱压向近黑，`look.crevice`）：画面收益很小，1440p 单帧却从 40 秒涨到 118 秒，所以关闭，配置里保留开关。

壳塔檐层另有专用材质：每层从绒簇顶的浅蓝向须边渐变到近黑，叠加竖向笔触，并带很弱的自发光（中景 0.042、远景 0.016、西侧独立壳塔 0.008，随同一渐变衰减）。渐变在檐层高度的 5%—68% 之间完成，所以每层下面三分之一是近黑的。西侧独立壳塔特意压暗：参考里铁拱架后面是黑的，拱架才读得出来；铁拱架自身带一点自发光也是为此。试过给拱架加一盏轮廓灯，结果只是把那一片雾照亮，已撤掉。参考里每层塔檐是一团亮蓝的绒簇衬着下面的黑缝，单靠场景灯光打不出这种逐层的明暗，所以把它画进材质。渐变取自檐层的 UV，不依赖光照方向。

## 6. 色彩管理

| 项目 | 取值 |
| --- | --- |
| 显示 | sRGB |
| 视图变换 | **Standard** |
| Look／曝光 | None／0 |
| 后期 | 合成器辉光（Bloom）：阈值 1.0、强度 0.4、尺寸 0.5 |

同一帧用 AgX 和 Standard 各渲一次比较过：AgX 把蓝色压得偏灰，Standard 保留参考那种饱和的深蓝，所以选 Standard。代价是高光直接截断，因此发光强度都压在接近 1 的范围内，灯球的柔光靠辉光后期给出。序列转 MP4 时序列场景同样用 Standard，不会二次变换。**对照期间不再改动这一组设置。**

机器：RTX 5060 Laptop 8 GB、i7-13700HX。全部是 2026-10-01 在样板工程上的实测，数字来自 `renders/previews/stage02/render_manifest.json`。

## 8. 雨

依据：`14_Rain/Rain_video.mp4`。本阶段把全部 1259 帧解码（25% 尺寸）并做了逐帧差分，另取第 301—480 帧按原尺寸分析。读取方式是逐帧静态分析，不是实时观看，也没有试听。

| 观察 | 结果 |
| --- | --- |
| 镜头 | 全程静止：首、中、尾各帧与第 1 帧对位偏移为 0 |
| 有效帧 | 1259 帧中 412 对相邻帧完全相同，规律为每三帧重复一帧；有效画面约 40 帧／秒 |
| 方向 | 竖直。左右错开 2 像素后相关性降到一半以下，没有可见倾角 |
| 雨丝宽度 | 中位 2 像素（2560 宽画面），约 0.02 单位 |
| 雨丝长度 | 中位 238 像素（约 2 单位），四分之一超过 455 像素，最长贯穿画面 |
| 数量 | 每帧约 110—216 条可辨雨丝 |
| 亮度与颜色 | 比背景亮约 0.12—0.19；浅蓝，约 (0.19, 0.41, 0.60) |
| 位移 | 相邻有效帧之间约 568 像素；相邻一帧与隔一帧的两组帧对结果相同（569 与 568），说明有效帧在时间上均匀 |

速度换算：画面中约 110 像素＝1 单位，568 像素约 5.2 单位；有效帧间隔按 1／40 秒计，**约 207 单位／秒**。这个位移峰很弱（去趋势后只有 0.003—0.004），画面的主要观感是「细长竖线在同一位置停留几帧、明暗闪动」，而不是可以跟踪的雨滴。所以速度是低置信度的估计，方向、粗细、长度和密度是高置信度的观察。

样板做法（`cot_look.build_rain`）：

- 雨是真实的细长三棱柱网格，分近、中、远三层，共 420 条轨迹（60＋150＋210），每条轨迹上一串长 8—44 单位的雨丝，占空约 0.55—0.6。按对照机位数，画面里同时可见的雨丝数量与视频的每帧 110—216 条同一量级。
- 24 帧／秒下每帧下移 8.6 单位（207÷24），整层以 96 单位为周期无缝循环，种子固定。
- 每条轨迹有随机相位并首尾环绕，所以任何高度上的雨量相同。第一版没有这样做，雨丝集中在周期的前段，循环滚动时整幅画面每 11 帧左右亮一次（逐帧平均亮度相邻帧最大相差 4.1）；改后相邻帧亮度差降到 0.7 以内。
- 有屋顶的范围（东侧楼屋盖下、西侧廊、高架廊桥面）不放雨丝；高台尖端和西侧走道上方也不放，因为雨丝是不被楼板截断的网格，放在那里会穿过楼板出现在板下。
- Z 62 以上（灰模下层长桥底面）透明；离镜头 4 单位以内淡出，避免贴脸的雨丝变成粗条。
- 发光色 (0.12, 0.30, 0.95)、强度 0.45、不透明度 0.24。

水面和积水的波纹由随帧数变化的四维噪声驱动；溢水水帘的条纹向下滚动。没有做落地水花。

## 8a. 描边（反向外壳）

第二轮先在雕像上试验；用户看过后选择推广，第三轮扩展到下表的网格构件。

| 项目 | 内容 |
| --- | --- |

| 范围（20 个网格） | 雕像四件；壳丘；广场石基；卵石；高架廊；东侧楼体、两段百叶屋盖、玻璃柱；西侧廊端及其屋盖；壳塔伸出的弧肋；壳塔塔身五座（中景 A、B，东侧楼顶，西侧独立，远景粉窗塔） |

| 墨色 | (0.0012, 0.0025, 0.01)。压暗场景后原来的 (0.004, 0.008, 0.03) 比背光的卵石还亮，线反而发亮，所以调暗 |
| 开关 | `config/plaza.json` 的 `look.outline`：`enabled`、`targets`（对象名前缀→系数）。集合 `COT_S2_OUTLINE` |
| 没有覆盖 | **铁艺**（路灯、栏杆、围栏、铁拱架、铁艺屏、字牌立杆）是曲线对象，外壳法不适用；它们本身就是细线，没有再加描边。窗框、灯球、铁桩、出水环、挑檐托以外的小件也没有加。近侧和最远的四座塔没有加 |
| 稳定性 | 描边是几何体，不是屏幕空间的线。推广前做了 2 秒（第 97—144 帧）测试：卵石区域相邻帧差中位 1.95、最大 2.15；雕像区域中位 5.57、最大 5.87；东侧楼区域中位 4.91、最大 6.47；整幅没有超过中位两倍的帧。证据在 `renders/previews/stage02/outline_motion_test/`。完整 10 秒预览的数据见检查报告 |
| 代价 | 推广后样板多了约 18 万顶点（共约 63 万）。2560×1440、96 采样对照机位：开 42.5 秒，关 39.0 秒。仅雕像时的差别不到半秒 |
| 对比过的另一种做法 | Freestyle 线条（只对雕像集合）：1280×720 单帧 42.5 秒，约为不开时的四倍。没有采用 |
| 灰模渲染 | Workbench 不认「只显示背面」的材质，会把外壳画成实心黑块，所以灰模模式下隐藏描边集合 |
